## 4. 六页结构

### 第 1 页｜封面：从金融问题到可验证的研究系统

- 主标题：`Vibe-Trading`
- 核心命题：`让自然语言金融研究，从“生成答案”走向“交付证据”`
- 视觉：复用全功能母版的研究流水线插画，配白底、深蓝标题、珊瑚红强调和底部品牌条。

### 第 2 页｜项目简介：Vibe-Trading 是什么

- 定义：面向金融研究与受控交易连接的自然语言 AI Agent。
- 输入：一个研究问题、策略假设或文件／网页材料。
- 系统过程：调用数据、文档、因子、回测、Swarm 与验证能力。
- 输出：结论、配置、交易、指标、警告和可复现的研究产物。
- 可信度数字：88 Skills、462 Alphas、23 Data Sources、30 Swarm Presets；动态 GitHub 数字不进入本短稿，避免快速过时。

### 第 3 页｜Motivation：会回答，不等于会研究

- 核心冲突：大模型擅长生成流畅观点，但金融决策需要可检验、可追溯、可重复。
- 三个转变：观点 → 假设；图表 → 证据；一次性回答 → 可复用研究资产。
- 视觉：左右对照，中间用“Research Gap”形成张力；左侧为普通对话输出，右侧为研究交付物。

### 第 4 页｜Challenges：真正困难的是把整条链做对

- 数据挑战：来源碎片化、市场异构、缺失与时间边界会改变结论。
- 研究挑战：前视偏差、幸存者偏差、参数过拟合和不可复现。
- 协作挑战：单一模型难以同时承担量化、基本面、风险和审计角色。
- 执行挑战：研究沙箱、模拟账户与受限实盘必须结构性隔离。
- 核心缺口：现有工具通常只优化一个环节，缺少贯穿输入、研究、验证和交付的统一运行时。
- 视觉：四个风险节点汇聚到中央“断裂的研究链”，避免纯项目符号页面。

### 第 5 页｜Solution：一个内核，贯穿五段研究闭环

- 五段主链：取证 → 研究 → 组合 → 验证 → 连接。
- 三层底座：Agent Runtime、Swarm、可审计 Artifact／Run Card。
- 安全边界：研究与回测保持沙箱；连接器默认只读；受控执行经过结构判别、mandate、kill switch 和 audit。
- 视觉：复用研究流水线语言，重新组织为五段主链和三层底座，不塞入全部工具名称。

### 第 6 页｜Outcome：把一次回答变成可复用的研究资产

- 输入：自然语言问题或策略假设。
- 交付：数据与配置、交易与指标、警告与归因、Run Card 与哈希产物。
- 能力证明：75／78 Agent Tools、54 MCP Tools、8 类回测引擎 + options、12 Trading Connectors。
- 收束句：`Vibe-Trading 的价值，不是替人给出一个答案，而是把研究过程变成可运行、可检验、可复用的系统。`
- 视觉：从一个问题进入系统，输出四类证据资产；使用深蓝结尾卡形成视觉收束。
